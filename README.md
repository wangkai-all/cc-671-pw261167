# 套餐偏好分析（本地虚构样本）

一个只依赖 Python 标准库的本地分析页：把“历史选择记录”当作带快照的多项选择数据，
拟合带价格与套餐属性的多项 Logit，并用同一组参数做菜单情景、替代来源和组合利润搜索。

> 所有套餐、价格、成本、历史记录和菜单情景均由 `app/synth.py` 在本地生成，
> **是虚构样本，不连接任何真实交易系统**。服务默认只监听 `127.0.0.1`。

## 运行

```bash
# 1) 生成虚构样本（可重复执行；写入 data/）
python3 -m app.synth

# 2) 启动本地页面
python3 -m app.server --port 8765
# 打开 http://127.0.0.1:8765/
```

服务启动时若样本文件不存在会自动生成。`data/` 下是生成产物，可随时删除重建。

## 测试

```bash
python3 -m pytest tests -q
```

测试覆盖：选择集校验、重复提交去重、未展示套餐不按零次成交、份额（含“都不选”）
归一、替代与承接平衡、组合搜索按整份菜单计算且尊重“必须保留入门档”、
诊断阻断情景/搜索，以及 HTTP 接口行为。

## 页面结构

| 页签 | 作用 |
| --- | --- |
| 数据与模型 | 记录示例、校验/去重结果、系数与支付意愿、诊断、相关性矩阵 |
| 菜单情景 | 勾选/定价/成本编辑菜单，查看整组份额、替代明细与利润变化 |
| 套餐详情 | 单款套餐的份额、撤下后的去向、加入时的来源、历史展示与选择率 |
| 组合搜索 | 最多 10 个候选、可限定菜单规模与必须保留的入门档，穷举整组利润 |
| 口径说明 | 数字口径、何时不给建议、数据来源 |

## 关键口径

1. **记录保存当时的菜单**：每条记录写入当时展示的套餐、各自价格/属性、被选项或
   “都不选”。未展示的套餐不进入该记录的选择集，也不会被当成零次成交。
2. **先校验再拟合**：被选项必须在展示集合内；重复提交按 `submission_id`
   （幂等键）去重，同一天同菜单同选择的两位不同用户各计一次。
3. **一项选择 = 一条似然**：拟合时每条记录正好贡献一个多项选择项，菜单用记录自己的
   快照，不按今日菜单回填。
4. **属性同向变化**：菜单中 Pearson（缩放后）相关 ≥ 0.9 的属性对会被点名，
   其支付意愿标为“不可分”，只能报告合计效应。
5. **整组计算**：所有份额来自同一次多项选择（含“都不选”）；替换、替代和组合利润
   都按整份菜单计算，绝不把各套餐单独预测值相加。释放份额与承接份额在数值上平衡。
6. **诊断优先**：不收敛、完全分离、价格系数非负/不显著、信息矩阵奇异或病态时，
   页面保留诊断并停用情景与搜索，不直接给经营建议。

## 目录

```
app/
  catalog.py    虚构套餐、价格时间线、促销、上市/停售与快照
  history.py    记录结构、选择集校验、幂等去重、数据集统计
  synth.py      虚构历史样本生成
  stats.py      无依赖线性代数、相关性、条件数、MNL 牛顿法拟合
  model.py      系数换算、诊断、支付意愿、情景效用
  scenario.py   菜单份额、替代/来源、位移平衡、组合穷举搜索
  analysis.py   样本加载与缓存、API 载荷组装
  server.py     标准库 HTTP 服务（静态页 + JSON API）
web/
  index.html, styles.css, app.js, charts.js
tests/          pytest 用例
data/           生成的虚构样本（可删除后重建）
```
